## Frontend

### Vue 3

Мой основной фреймворк, 2+ года каждый день. Пишу на Composition API и `<script setup>`.

- Работал над 6 приложениями финтех-платформы: кабинетом инвестора, CRM, сервисом авторизации и UI-kit.
- Делаю generic-компоненты (например, `DataTable<T>`) и динамические формы, которые строятся по JSON-схеме.
- Логику выношу в composables. Компоненты отвечают только за отображение.

### Nuxt

Использую для сайтов, где важны SEO и скорость первой загрузки.

- В одиночку переписал билетную афишу на Nuxt 4 с SSR. Каждый город работает на своём поддомене, город определяется по хосту.
- SEO: мета-теги, JSON-LD, динамические `sitemap.xml` и `robots.txt`.
- Публичная часть рендерится на сервере, админка работает в режиме CSR. Есть PWA с офлайн-страницей.

### TypeScript

Пишу в strict-режиме и стараюсь обходиться без `any`.

- Перевёл кабинет инвестора с JavaScript на TypeScript: настроил компилятор, типизировал утилиты и динамические формы.
- Настроил генерацию API-клиента из Swagger через Kubb: типы, Zod-схемы и хуки Vue Query создаются автоматически.
- Статусы и роли храню в типизированных справочниках вместо «магических» строк.

### JavaScript

База под всем остальным: ES2022+, асинхронность, работа с DOM и браузерными API.

### Pinia

- Сделал централизованный сервис модальных окон и сохранил обратную совместимость со старым API.
- В Pinia храню состояние клиента: пользователя, токены, UI. Серверные данные держит TanStack Query.

### TanStack Query

- Кэширую серверные данные, инвалидирую связанные запросы после мутаций, пагинирую через `keepPreviousData`.
- Сделал обновление транзакций без перезагрузки страницы и защиту от повторных платежей.

### Zod

- Проверяю ответы бэкенда по схемам: если контракт с API разошёлся, ошибка видна сразу, а не в интерфейсе.
- На бэкенде валидирую входные данные и конфигурацию окружения.

### HTML / CSS

- Адаптивная вёрстка с mobile-first подходом. На узких экранах таблицы превращаются в карточки, навигация — в бургер-меню.
- Использую семантическую разметку и доступность: `aria-*`, фокус, `prefers-reduced-motion`.
- Методология БЭМ.

### Tailwind CSS

Использую в публичном сайте и админке билетной платформы.

### SCSS

Использую в UI-kit: ввёл дизайн-токены цветов, собрал SVG-спрайт иконок, адаптировал компоненты под планшеты и мобильные.

## Backend

### Node.js

Пишу на нём бэкенд и вспомогательные скрипты.

- Скрипты миграции данных со старой системы: логирование ответов в JSONL, импорт и дедупликация.
- Синхронизация каталога с внешним API по cron.

### Express

Бэкенд билетной платформы на TypeScript.

- JWT-авторизация и ролевая модель из 4 ролей, пароли хешируются через bcrypt.
- Безопасность: helmet, CORS для поддоменов, rate-limit.
- Загрузка и обработка изображений (multer, sharp), YML-фиды и отчёты.

### Prisma

Описываю схему и миграции. Синхронизация с внешним API работает через upsert по `external_id`.

### PostgreSQL

Сам спроектировал схему БД билетной платформы: города, площадки, мероприятия, сеансы, жанры и связи между ними.

### REST API

- Проектирую эндпоинты для админки. Чтобы не сломать существующих клиентов, оставил старый формат API рядом с новым.
- Во фронтенд-команде согласовывал API-спецификации с бэкендом.

## Инструменты

### Vite

Вынес UI-kit в изолированную сборку, которая подключается как npm-пакет и git submodule. Добился одинаковой сборки на Windows и macOS, обновил проект до Vite 8 / Rolldown.

### Vitest

Бизнес-логику пишу чистыми функциями и покрываю unit-тестами. Компоненты тестирую через Vue Test Utils. В демо-проекте 98 тестов.

### Git

1 000+ коммитов в командных репозиториях. Работаю с feature-ветками и делаю code review.

### Nginx

Настраиваю как reverse proxy: поддомены, отдача статики.

### PM2

Запускаю Node.js-приложения в продакшене и перезапускаю их при сбоях.
